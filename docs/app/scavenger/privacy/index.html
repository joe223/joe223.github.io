Privacy policy

0.1.0 · 2026-10-23

About this policy

Scavenger is developed by Zachari. This policy describes the current 0.1.0 application and these support pages. Contact orinoapp@163.com with privacy questions or deletion requests about information you voluntarily send to support. The app is currently in development; final signed distribution must match this policy.

Local processing and network activity

Scavenger does not provide an account, cloud synchronization, advertising, behavioral analytics, telemetry uploads or an automatic updater. The app does not send file names, paths, scan results or usage activity to the developer or third parties, and does not sell that information. Opening a support or privacy link uses your system browser without adding scan data to the URL. Apple permissions, diagnostics and App Store services follow Apple’s policies and your settings.

What analysis reads

Analysis begins only after you choose Deep Analysis or Quick Cleanup. Within accessible, authorized locations it reads file-system metadata and bounded app-identity fields from Info.plist files. For supported local AI-tool indexes, it uses read-only queries for identifiers, titles, projects, dates and status fields. It does not query message bodies, independent prompt fields, credentials or arbitrary database blobs. Some known JSON metadata files are read with size and count limits before header fields are decoded; other bytes may enter memory but are not indexed or displayed. Titles and paths can themselves contain personal information or snippets saved by the original tool. Unknown formats are counted by storage size rather than parsed as conversations.

Scope and authorization

Sandboxed builds use the macOS folder picker and saved app-scoped bookmarks. The app’s user-selected read/write entitlement allows separately confirmed cleanup; scanning code uses read-only access and saved read-only bookmarks. This is an application behavior boundary, not a claim that every operating-system grant is inherently read-only. Existing targets and grants are not automatically broadened. Scans do not automatically enter other mounted volumes or enumerate all APFS snapshots. Access ends when the task finishes, fails or is canceled.

Information saved on this Mac

Targets and their names, sources and directory bookmarks are stored in Scavenger/scopes.json under the app’s Application Support directory; the sandboxed build uses its app container. Appearance preferences are stored in local UserDefaults. Scan results and system/app memory summaries are held in process memory rather than saved as scan history. A private temporary SQLite index may hold deduplication identifiers and session titles, projects, dates and sizes during a task. It is removed at normal completion; after an abnormal exit it may remain until temporary-file cleanup. Settings files use permissions limited to the current user.

Supported session data and app icons

Scavenger inspects supported local records; it does not connect to accounts or fetch cloud history. Database queries are read-only, do not migrate user databases and do not create missing database side files. Configuration and credential files may contribute to size totals without their contents being read. The app obtains installed-app icons from macOS for display and caches them in memory; it does not launch those apps or download brand images. System and Scavenger memory summaries do not inspect other apps’ memory contents.

Optional, confirmed cleanup

Analysis does not modify scanned objects. Cleanup requires explicit selection and one exact-list confirmation for every operation. In sandboxed builds, a system parent-folder picker first grants temporary write access and does not itself clean files; that write grant is used only for this operation and is not persisted. Scavenger rechecks scope, identity and content before processing. Supported dependencies, independent session records, reviewed caches and logs move through the system Trash API. An explicitly selected eligible ordinary folder from the disk map includes all its contents, including source code, Git history and personal files; this manual action is not automatic junk identification. A separate, clearly labeled action permanently deletes only whitelisted rebuildable caches: ~/Library/Caches/go-build, ~/.cache/go-build, and ModuleCache.noindex or SDKStatCaches.noindex directly within ~/Library/Developer/Xcode/DerivedData. It bypasses Trash, cannot be undone and requires the same exact-list confirmation. The entire DerivedData folder is not permanently deleted. Scavenger does not empty Trash, automatically clean in the background, stop other apps or run package-manager commands. Shared or multi-file session stores remain managed by their original app. Concurrent changes and APFS accounting mean the operation is not an atomic snapshot or a guarantee of released space.

Your controls and retention

You can cancel analysis and remove saved targets. Grants no longer referenced by targets are removed; clearing all targets removes all saved grant records. The next Start Analysis may request a location again. Removing settings or grants does not delete scanned files or revoke unrelated macOS permissions. You can remove retained app settings using macOS file management after quitting Scavenger.

Support messages

If you email support, the developer receives the information you choose to send and uses it to answer your request. It is retained only as needed to resolve that request or meet legal obligations. You may request deletion by email. Please redact paths, project names and conversation titles, and do not send passwords, payment details, session databases or unrelated private files.

These web pages

These static pages do not include analytics, ads, tracking cookies or third-party scripts. Typography uses system fonts without third-party font requests. GitHub Pages processes technical request information under GitHub’s privacy statement. An explicitly chosen display language is stored only in your browser and is not transmitted by the page.

Changes

Last updated October 23, 2026. If app behavior changes, this policy and relevant permission or store disclosures should be updated before those features are released.
